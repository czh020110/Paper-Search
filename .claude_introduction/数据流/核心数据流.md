# 核心数据流

## 技术栈

Python 3.10+, FastAPI, Uvicorn, httpx, langchain, langchain-openai, langgraph, dashscope, rank-bm25, pydantic, 标准库（argparse, json, pathlib, dataclasses, unittest, concurrent.futures, hashlib, threading）

## 端到端筛选链路（live backend）

### 链路目标

通过 live backend 调用 Semantic Scholar 与 OpenAlex 双源学术检索 API，经查询理解、初检索、（可选）arXiv/DBLP 辅助检索、三级筛选（粗筛/中筛/精筛）、滚雪球扩展后输出 result.md + graph.json + experiment.json 三类产物；CLI 与 FastAPI Web 入口复用同一条 pipeline。

### 数据流

[CLI / FastAPI 入口] -> [加载配置（env > config.local.json > default）] -> [初始化日志/预算/缓存] -> [查询理解（live: LLM invoke + `_parse_query_plan_json` 解析 / mock: 规则）] -> [live 初检索（S2 顺序 + OA 并行 + arXiv 并发 + DBLP 并行，含缓存/预算/API 参数翻译）] -> [去重排序] -> [字段补全 (enrichment): 跨源标题搜索补全缺失 venue/abstract，仅 live 模式] -> [候选池入池(status=seed)] -> [粗筛（三路混合打分：BM25 + Embedding + Structure，≤40跳过，含 Embedding 硬底线和相对阈值截断）] -> [中筛（Reranker API 重排序，DashScope qwen3-rerank / SiliconFlow BAAI/bge-reranker-v2-m3，Top-30 + 相对阈值，RERANKER_ENABLED 独立开关，RERANKER_QUERY_MODE 控制 combined/max_per_query 两种查询模式）] -> [精筛（LLM invoke + JsonOutputParser 100并发单篇三分类判定）] -> [滚雪球扩展（精筛后执行：LLM invoke + `_parse_json_array` query evolution + API re-search + 引文扩展 + 收敛循环）] -> [golden set 评测] -> [输出写入 (result.md + graph.json + experiment.json + query_plan.json)]

### 输入

- 自然语言查询
  - 来源：用户（CLI 参数 / FastAPI GET/POST 请求 / Web 页面输入框）
  - 关键字段：query 字符串
  - 约束：非空字符串；支持中文/英文混合学术查询

### 处理步骤

#### 入口层

1. `paper_search/cli.py::main` / `paper_search/web.py::api_search_get` / `paper_search/web.py::api_search_post`
   - 职责：解析命令行参数或接收 HTTP 请求，加载配置，调用 pipeline
   - 调用方：用户命令行、浏览器页面、Swagger UI、其他 HTTP 调用方
   - 被调用方：`load_settings`, `run_pipeline`
   - 调用时机：用户执行 CLI 命令、访问 `/api/search`，或通过 `/search` 页面提交查询
   - 输入：CLI 参数（query, backend, output-dir, serve, host, port）或 HTTP 请求参数（q / query）
   - 输出：CLI 输出 JSON 摘要；FastAPI 返回 JSON 结果；Web 页面展示候选论文与输出文件概览
   - 状态变化：无
   - 异常分支：query 为空时报错；backend 不支持时报错；Web 错误返回 JSONResponse(status_code=400)

#### 配置与基础设施层

2. `paper_search/config.py::load_settings`
   - 职责：从环境变量/`config.local.json`/默认值三级优先级加载运行配置，返回 Settings 对象并生成 config snapshot
   - 调用方：cli.py, web.py
   - 被调用方：`_load_private_config`, `_resolve`, `BudgetLimits`
   - 调用时机：CLI 启动、Web 模块初始化时
   - 输入：环境变量（CACHE_DIR, OUTPUT_DIR, LOG_LEVEL, LLM_PROVIDER, LLM_MODEL, LLM_FAST_MODEL, OPENAI_API_KEY, DASHSCOPE_API_KEY, SILICONFLOW_API_KEY, ZHIPUAI_API_KEY, 各 Embedding/Reranker API Key）和可选的 `config.local.json`
   - 输出：Settings（cache_dir, output_dir, log_level, llm_api_base, llm_model, llm_fast_model, runtime_config（含 `llm_api_key_set`，检查当前 Provider 对应 Key 是否存在）, experiment_config, budget_limits()）
   - 状态变化：无
   - 异常分支：`config.local.json` 不存在或 JSON 解析失败时回退空字典

3. `paper_search/logging_config.py::setup_logging`
   - 职责：配置结构化 JSON 日志（pipeline.jsonl）+ 控制台日志双输出
   - 调用方：pipeline.py
   - 被调用方：logging 标准库
   - 调用时机：pipeline 启动时第一时间
   - 输入：run_id, log_dir, log_level
   - 输出：配置 paper_search logger 的双 handler（文件 JSON + 控制台可读）
   - 状态变化：创建 logs/{run_id}/ 目录
   - 异常分支：无（自动创建目录）

4. `paper_search/budget.py::BudgetController`
   - 职责：强制控制 API 调用次数、Token 使用量、迭代轮数、候选池大小的硬上限
   - 调用方：pipeline.py, live_backend.py, snowball/\_\_init\_\_.py
   - 被调用方：无
   - 调用时机：pipeline 初始化时创建，全链路复用
   - 输入：BudgetLimits（来自 experiment_config.selection.budget）
   - 输出：can_call_api / can_use_tokens / can_start_round / can_expand_pool 布尔决策 + usage_summary
   - 状态变化：内部计数器（api_calls_used, tokens_used, current_round）
   - 异常分支：无（超出限制时记录 warning 并返回 False，不抛异常）

5. `paper_search/cache.py::CacheStore`
   - 职责：文件级缓存，按 domain 分目录存储 JSON 数据，支持 TTL 过期与版本失效
   - 调用方：pipeline.py, live_backend.py, openalex.py, semantic_scholar.py
   - 被调用方：hashlib, json, threading
   - 调用时机：pipeline 初始化时创建（仅 live 模式），检索阶段读写
   - 输入：cache_dir；get/put 操作含 domain + key parts + 数据
   - 输出：get 返回缓存数据或 None；stats/hit_rate 返回统计
   - 状态变化：文件系统读写；内部 hit/miss 计数器
   - 异常分支：无（缓存未命中返回 None，静默回退到 API 调用）

6. `paper_search/pool.py::CandidatePool`
   - 职责：候选池状态机，管理论文从 discovered → seed → expanded → rough_scored → reranked → llm_judged → selected/excluded 的完整生命周期
   - 调用方：pipeline.py, snowball/\_\_init\_\_.py, screening/*.py
   - 被调用方：无
   - 调用时机：pipeline 内去重排序后创建，全筛选链路复用
   - 输入：add(paper, status)；transition(paper_id, new_status)；transition_all(current_status, new_status)
   - 输出：by_status(status) 返回对应状态的论文列表；summary() 返回状态计数
   - 状态变化：论文 pool_status 字段按 VALID_TRANSITIONS 约束流转
   - 异常分支：非法状态或非法转换时抛出 InvalidTransition

7. `paper_search/errors.py`
   - 职责：统一错误分类基座（PaperSearchError 及其子类），httpx 异常到内部错误的映射
   - 调用方：openalex.py, semantic_scholar.py, live_backend.py
   - 被调用方：无
   - 调用时机：外部 API 调用发生异常时
   - 输入：httpx 异常对象
   - 输出：PaperSearchError 子类实例（ApiTimeoutError / ApiRateLimitError / ApiError）
   - 状态变化：无
   - 异常分支：无（纯工具函数）

#### 查询理解层

8. `paper_search/query_understanding.py::build_query_plan`
   - 职责：解析自然语言查询，识别查询类型（navigational/semantic/metadata），提取硬约束、排序信号、语义关键词、子查询和 API 参数翻译。live 模式通过 `_build_query_plan_llm`（内部函数）调用 LangChain ChatOpenAI + `with_structured_output`（通过 `get_structured_output_llm` 禁用 thinking 模式），使用 `QueryPlanSchema` Pydantic schema 强制 LLM 输出符合 schema 的 structured output；类型/数量/结构约束由 Pydantic 承担，跨字段规则由 prompt 承担；LLM 调用或结构化输出失败时直接抛出 `RuntimeError`，不再静默降级到低质量规则路径；mock/测试走规则路径
   - 调用方：pipeline.py
   - 被调用方：`_build_query_plan_llm`（LLM 路径，内部函数，`with_structured_output` + `QueryPlanSchema`） / `_build_query_plan_rules`（规则实现）
   - 调用时机：pipeline 内第一步
   - 输入：query 字符串, use_llm 标志
   - 输出：QueryPlan（original_query, intent_analysis, hard_filters, ranking_signals, semantic_queries, sub_queries_for_retrieval: 搜索意图摘要，不直接发往API，用于reranker/雪球/结果展示, api_payload_translation: 查询理解→初检索的唯一输入源，S2/OA各自独立生成搜索策略, query_expansion_policy）
   - 状态变化：无
   - 异常分支：对应 Provider 的 API Key 未配置时通过 `is_llm_key_configured()` 检测并直接报错不静默回退，错误信息提示设置 `${LLM_PROVIDER}_API_KEY`；LLM 调用失败时直接抛出 `RuntimeError`，不再 fallback 到规则路径

#### 检索层

9. `paper_search/retrieval/live_backend.py::retrieve_live_papers`
   - 职责：基于 QueryPlan 的 query_type 路由 live 检索策略：S2/OA 优先使用 api_payload_translation（通过 `_parse_oa_payload` 解析 OA payload，支持新版结构化 `OAFilterSchema` 和旧版裸字符串 filter 两种格式，含 `_oa_normalize_year` 将 S2 格式年份转为 OA 兼容格式，`publication_year` 不支持 `>=` 运算符时自动迁移到 `from_publication_date`；通过 `_parse_s2_payload` 解析 S2 payload，支持新版结构化 S2PayloadSchema（含 venue/fields_of_study/publication_types/min_citation_count/open_access_pdf/sort/limit 等字段）和旧版 query + year 两种格式），回退到英文查询构建（`_build_english_queries`，仅 english_core 非空时拼接变体）。S2 与 OA 的 api_payload_translation 由 query_understanding 各自独立生成，S2 偏向语义长句+结构化过滤，OA 偏向 BM25 关键词句子+filter 字段，二者数量/策略可不一致，不强制一一对应。arXiv 使用 `sub_queries_for_retrieval` 作为搜索意图摘要（语义搜索引擎，无需密钥）；DBLP 同样使用 `sub_queries_for_retrieval`（公共 JSON API，无需密钥）。sub_queries_for_retrieval 不再作为 S2/OA 的 API 搜索词输入——api_payload_translation 是 S2/OA 检索的唯一输入源。四个搜索源可通过 `SEARCH_SOURCE_S2` / `SEARCH_SOURCE_OA` / `SEARCH_SOURCE_ARXIV` / `SEARCH_SOURCE_DBLP` 环境变量独立禁用（默认均为 true），对应源关闭时跳过检索不创建 callable；无 S2 API key 时 S2 封装为 `_run_s2_sequential` 单线程执行、OA/arXiv/DBLP 线程池并发（`_run_s2_one` 辅助函数支持预算校验）；有 S2 API key 时全部线程池并发；全程每任务校验预算
   - 调用方：pipeline.py
   - 被调用方：`search_papers`, `search_papers_by_title`, `search_works`, `search_works_by_title`；`BudgetController.can_call_api`；`CacheStore.get/put`
   - 调用时机：backend=live 时的检索阶段
   - 输入：QueryPlan, CacheStore | None, BudgetController | None
   - 输出：list[Paper], list[dict]（检索论文列表和当前边集合）
   - 状态变化：BudgetController 内部计数器递增
   - 异常分支：单个 API 任务失败时记录 warning 并继续其他子查询；预算耗尽时跳过剩余任务
   - 调用方：pipeline.py
   - 被调用方：`search_papers`, `search_papers_by_title`, `search_works`, `search_works_by_title`；`BudgetController.can_call_api`；`CacheStore.get/put`
   - 调用时机：backend=live 时的检索阶段
   - 输入：QueryPlan, CacheStore | None, BudgetController | None
   - 输出：list[Paper], list[dict]（检索论文列表和当前边集合）
   - 状态变化：BudgetController 内部计数器递增
   - 异常分支：单个 API 任务失败时记录 warning 并继续其他子查询；预算耗尽时跳过剩余任务

10. `paper_search/retrieval/semantic_scholar.py::search_papers` / `search_papers_by_title`
    - 职责：调用 Semantic Scholar Graph API，按标题精确检索或通用语义检索返回论文数据；集成缓存和错误分类重试。`build_s2_params()` 将 `S2PayloadSchema`（8个字段）转换为 S2 API 查询参数；`search_papers()` 新增关键字参数 `s2_payload`（S2PayloadSchema | None），传入时优先使用结构化 payload 构建参数，未传入时回退到旧版 `query + year_from + limit` 签名
    - 调用方：live_backend.py
    - 被调用方：`httpx.get`；`CacheStore.get/put`；`classify_httpx_error` / `is_retryable`
    - 调用时机：navigational 查询走标题路径；其他查询走通用搜索路径
    - 输入：query/title, year_from, limit, cache, s2_payload（S2PayloadSchema | None，关键字参数，非 None 时优先使用 `build_s2_params()` 构建参数，忽略旧版 year_from/limit）
    - 输出：list[Paper]（source_api=semantic_scholar）
    - 状态变化：无（缓存写入文件系统）
    - 异常分支：429 等可重试错误按退避重试最多 3 次；不可重试错误直接返回空字典；最终失败返回空列表

11. `paper_search/retrieval/openalex.py::search_works` / `search_works_by_title`
    - 职责：调用 OpenAlex Works API，按标题或通用搜索返回论文数据并重建摘要字段；支持分页游标循环；集成缓存和错误分类重试。支持新的 `oa_filter`（`OAFilterSchema`，含 11 个结构化 filter 字段，通过 `build_oa_filter_string` 转为 OpenAlex filter 字符串）、`sort`（排序参数，如 `relevance_score:desc`）参数。使用 `_build_common_params` 统一处理 `mailto` + `api_key` 参数
    - 调用方：live_backend.py
    - 被调用方：`httpx.get`；`CacheStore.get/put`；`classify_httpx_error` / `is_retryable`；`_build_common_params`；`build_oa_filter_string`
    - 调用时机：与 Semantic Scholar 配套执行；OA 侧使用线程池并行发起多条子查询
    - 输入：query/title, oa_filter（OAFilterSchema | None）, sort（str | None）, per_page, cache
    - 输出：list[Paper]（source_api=openalex）
    - 状态变化：无（缓存写入文件系统）
    - 异常分支：同 Semantic Scholar；分页游标为 None 或空结果时自动终止循环

12. `paper_search/retrieval/arxiv.py::search_arxiv` / `search_arxiv_by_title`
    - 职责：调用 arXiv 公共 API（无需密钥），按通用搜索或标题搜索返回论文，解析 Atom XML 为 Paper 对象
    - 调用方：live_backend.py（navigational 查询或通用查询时作为辅助检索源）
    - 被调用方：`httpx.get`；`xml.etree.ElementTree`
    - 调用时机：与 S2/OA 配套执行；超时 8s + 1 次重试，避免拖慢管线
    - 输入：query/title, max_results, year_from
    - 输出：list[Paper]（source_api=arxiv）
    - 状态变化：无
    - 异常分支：XML 解析失败或请求超时返回空列表

13. `paper_search/retrieval/dblp.py::search_dblp` / `search_dblp_by_title`
    - 职责：调用 DBLP 公共 JSON API（无需密钥），按通用搜索或标题搜索返回论文，解析 JSON 为 Paper 对象。调用方（live_backend）直接使用 `sub_queries_for_retrieval`（LLM 翻译的英文子查询）做通用搜索
    - 调用方：live_backend.py（辅助检索源）
    - 被调用方：`httpx.get`
    - 调用时机：与 S2/OA 配套执行；线程池并发运行（有/无 S2 key 两套代码路径均不单独顺序延迟）
    - 输入：query/title, max_results
    - 输出：list[Paper]（source_api=dblp）
    - 状态变化：无
    - 异常分支：JSON 解析失败或请求超时返回空列表
    - 调用方：live_backend.py（辅助检索源）
    - 被调用方：`httpx.get`
    - 调用时机：与 S2/OA 配套执行；超时 15s + 最多 3 次重试
    - 输入：query/title, max_results
    - 输出：list[Paper]（source_api=dblp）
    - 状态变化：无
    - 异常分支：JSON 解析失败或请求超时返回空列表

14. `paper_search/dedupe.py::dedupe_papers` + `paper_search/pipeline.py::_rank_papers`
    - 职责：基于 DOI / ArXiv ID / S2 paperId / OpenAlex ID / 归一化标题做多级去重，并按年份、引用数、标题进行基础排序。去重合并时保留所有发现来源（`sources` 列表去重合并，primary 来源优先）。`normalize_title` 已作为公共函数导出，供 enrichment 模块跨源标题匹配使用。
    - 调用方：pipeline.py
    - 被调用方：无
    - 调用时机：live/mock 检索结果汇总后
    - 输入：Iterable[Paper]
    - 输出：list[Paper]（去重排序后论文列表，sources 字段合并了所有发现来源）
    - 状态变化：无（状态在 CandidatePool.add 时分配）
    - 异常分支：无

14.5. `paper_search/retrieval/enrichment.py::enrich_papers`
    - 职责：字段补全模块。对缺失 venue/abstract 的论文，依次按标题通过 S2 和 OA 做精确搜索补全。仅在 live 模式、去重后、入池前调用。
    - 调用方：pipeline.py（live 模式，去重排序后、CandidatePool.add 前）
    - 被调用方：`_try_enrich_from_s2`（内部调用 `semantic_scholar.search_papers_by_title`）、`_try_enrich_from_oa`（内部调用 `openalex.search_works_by_title`）、`_find_title_match`（使用 `normalize_title` 做精确标题归一化匹配）、`_backfill`（回填缺失的 venue/abstract/authors/citation_count/reference_count/publication_date/url/source_ids，并将 enrichment 来源追加到 paper.sources）
    - 调用时机：live 模式去重后，仅对 venue 或 abstract 缺失的论文执行
    - 输入：list[Paper], CacheStore | None, BudgetController | None
    - 输出：list[Paper]（字段补全后的同一列表，修改 in-place）
    - 状态变化：论文缺失字段被补全；sources 列表追加 enrichment 来源（"semantic_scholar" 或 "openalex"）
    - 异常分支：单个论文 enrichment 失败时记录 warning 并继续；预算耗尽时跳过 API 调用

#### 筛选层（S-006/S-007/S-008，已实现）

15. `paper_search/screening/coarse.py::coarse_score`
    - 职责：BM25 + Embedding + Structure 三路混合打分与截断；候选池 ≤ COARSE_POOL_SKIP_THRESHOLD(默认40) 时跳过
    - 调用方：pipeline.py
    - 被调用方：`_bm25_score`（rank-bm25 关键词匹配）、`_embedding_scores`（Embedding 余弦相似度，DashScope text-embedding-v4 / SiliconFlow BAAI/bge，通过 `paper_search/embedding.py` 调用）、`_structure_score`（年份接近度 + log1p(引用数) + venue 模糊匹配）、`_minmax_norm`（归一化）
    - 调用时机：初检索完成后
    - 输入：CandidatePool, QueryPlan
    - 输出：list[Paper]（rough_scored 状态论文）
    - 权重：有 Embedding 时 0.35×BM25 + 0.35×Embedding + 0.30×Structure（可配置）；无 Embedding 时 0.60×BM25 + 0.40×Structure
    - 截断：combined < mean × COARSE_RELATIVE_THRESHOLD_FACTOR(0.3) → excluded；cosine_sim < COARSE_EMBEDDING_MIN_SIMILARITY(0.35) → 硬排除
    - 状态变化：seed/expanded → rough_scored（通过）/ excluded（截断）
    - 异常分支：无种子论文时记录 info 并返回空列表；Embedding API 不可用时退化为双路；Embedding 速率限制通过 Token Bucket 限流器（EMBEDDING_RPS_LIMIT=15, EMBEDDING_CONCURRENCY=10）保证

16. `paper_search/screening/reranker.py::rerank`
    - 职责：Reranker 高精度重排序（DashScope qwen3-rerank SDK / SiliconFlow BAAI/bge-reranker-v2-m3 OpenAI 兼容 API），相对阈值 + Top-K 保底，RERANKER_ENABLED 独立开关控制。query 构建支持两种模式：**combined**（默认，将 `sub_queries_for_retrieval` 拼成一行调 1 次 reranker）和 **max_per_query**（每条子查询分别调 reranker，每篇论文取最高分）。query 来源已从 `original_query + core_concepts` 改为 `sub_queries_for_retrieval`（纯英文 LLM 翻译子查询），避免中文查询导致中英文结果打分不公平
    - 调用方：pipeline.py
    - 被调用方：`_call_rerank_dashscope`（DashScope TextReRank SDK）/ `_call_rerank_siliconflow`（httpx POST）、CandidatePool.transition
    - 调用时机：粗筛完成后
    - 输入：CandidatePool, QueryPlan
    - 输出：list[Paper]（reranked 状态论文）
    - 阈值：score ≥ mean × RERANKER_RELATIVE_THRESHOLD_FACTOR(0.7) 或 Top-RERANKER_TOP_K_FALLBACK(30) 保底
    - 状态变化：rough_scored → reranked（通过）/ excluded（截断）
    - 异常分支：RERANKER_ENABLED=false 或无 RERANKER_PROVIDER 时 pass-through 全量透传；API 失败时 fallback 零分

17. `paper_search/screening/judge.py::judge`
    - 职责：LLM 并发单篇相关性判定（三分类：高度相关/部分相关/不相关 + 理由 + 贡献），使用 LLM 裸 `invoke` + `JsonOutputParser` 解析 JSON 输出，再手动提取字段；LLM 调用失败时默认纳入（高度相关）以保底
    - 调用方：pipeline.py
    - 被调用方：`_judge_single`（单篇 LLM 调用，使用 LLM_FAST_MODEL + `JsonOutputParser`）、`_judge_wave`（ThreadPoolExecutor 并发 wave）
    - 调用时机：中筛完成后
    - 输入：CandidatePool, QueryPlan
    - 输出：list[Paper]（selected 状态论文）
    - 并发：JUDGE_CONCURRENCY=100 workers，JUDGE_WAVE_CAP=5000 篇/波
    - 状态变化：reranked → llm_judged → selected（高度相关/部分相关 或 LLM 失败）/ excluded（不相关）
    - 异常分支：通过 `is_llm_key_configured()` 检测对应 Provider 的 API Key 未配置时，pass-through 全部透传为高度相关（不报错），并记录日志；单篇 LLM 失败时默认纳入（高度相关）

#### 滚雪球扩展层（S-005，已实现）

18. `paper_search/snowball/__init__.py::run_snowball`
    - 职责：LangGraph StateGraph 驱动的迭代式检索闭环（query_evolution → re_search → expand_citations → check_convergence）。图编译结果缓存在模块级单例中以避免重复编译。精筛后执行，利用 LLM 判定结果（高度相关/部分相关）作为关键词提取和引文扩展的种子
    - 调用方：pipeline.py（仅 live 模式；mock 模式跳过）
    - 被调用方：`_get_snowball_graph`（模块级单例）；LangGraph 节点函数（`_query_evolution`, `_re_search`, `_expand_citations`, `_check_convergence`）；`CandidatePool`, `BudgetController`, `CacheStore`
    - 调用时机：精筛完成后，仅当 backend="live" 时执行
    - 输入：CandidatePool, QueryPlan, BudgetController, CacheStore | None, max_rounds
    - 输出：tuple[CandidatePool, list[dict]]（更新后的候选池和引文边集合）
    - 状态变化：候选池论文状态可能从 llm_judged 转为 expanded；新增引文边到 edges 列表
    - 异常分支：LangGraph 不可用时记录 warning 并跳过；收敛条件（overlap>70%、无新关键词、达到最大轮数、预算耗尽）触发自动停止
    - 节点实现：
      - `_query_evolution`：从 llm_judged 状态的高分论文中取 Top-5，通过 LLM_FAST_MODEL 裸 `invoke` + `_parse_json_array` 提取 1-10 个新英文关键词（去除已存在关键词后去重）
      - `_re_search`：用新关键词分别调用 S2 search_papers 和 OA search_works API 补召回，去重后以 status="expanded" 加入候选池，计算重叠率
      - `_expand_citations`：对高度相关论文取 Top-3，通过 S2 get_paper_citations/get_paper_references 和 OA get_work_citations/get_work_references 获取双向引文并记录 CitationEdge 到 edges
      - `_check_convergence`：校验重叠率>70%、无新关键词、达到最大轮数 3 或预算耗尽时收敛

24. `paper_search/schemas.py`
    - 职责：Pydantic v2 BaseModel 层次结构，为查询理解 LLM 输出提供类型/数量/结构约束和 Field(description) 内容指导。QueryPlanSchema 包含 IntentAnalysisSchema, HardFiltersSchema, RankingSignalsSchema(preferred_venues: list[str]), SemanticQueriesSchema, ApiPayloadTranslationSchema(内含 S2PayloadSchema/OAPayloadSchema 单条 payload 类型), QueryExpansionPolicySchema(`model_construct` 用于 LLM 输出缺失时填充默认值)。`OAPayloadSchema` 已从裸 `search` + `filter` 字符串升级为结构化格式：`search: str | None`（BM25 关键词匹配，要求精简关键词句子而非自然语言）、`filter: OAFilterSchema`（含 11 个 filter 字段，其中 publication_year 仅接受单年份或闭区间，不支持 `>=` 运算符，`from_publication_date` 用于"since year X"开放范围；`primary_location_source_id` 明确禁止编造 ID）、`sort: str | None`、`per_page: int`。`S2PayloadSchema` 从 2 字段（query + year）升级为 8 字段：query（语义搜索，支持自然语言短语和 AND/OR/NOT）、year（可选）、venue、fields_of_study、publication_types、min_citation_count、open_access_pdf、sort、limit（默认 20，最大 1000）。S2 与 OA 各自的 payload 描述已改为突出其搜索引擎特性差异：S2 强调语义搜索优势（自然语言短语、AND/OR/NOT、结构化过滤），OA 强调 BM25 关键词策略（精简关键词句子、filter 字段）。ApiPayloadTranslationSchema 的 description 已移除"one entry per sub_query"约束，明确 S2 与 OA 的策略独立。sub_queries_for_retrieval 的 min_length 从 3 降为 2，description 改为"搜索意图摘要，不直接发往API"。精筛判定和雪球关键词提取不再依赖 Pydantic schema 进行结构化输出（改用裸 `invoke` + `JsonOutputParser` / `_parse_json_array`），JudgeVerdict 和 KeywordList 模型已从 schemas 中移除
    - 调用方：query_understanding.py, screening/judge.py, snowball/__init__.py
    - 被调用方：QueryPlanSchema.to_query_plan() 转换为 contracts.QueryPlan；`build_oa_filter_string` 消费 OAFilterSchema
    - 原则：Pydantic 承担类型/数量/结构/内容约束；prompt 只保留跨字段规则

### 状态流转

- 成功路径（live）：query -> QueryPlan(LLM invoke + `_parse_query_plan_json`) -> 四源并行初检索（S2 通过 `_parse_s2_payload` 解析新/旧格式 payload，`build_s2_params` 转为 API 查询参数） -> 去重排序 -> 字段补全 (enrichment: 跨源标题搜索补全缺失 venue/abstract) -> CandidatePool(seed) -> coarse_score(rough_scored, 三路加权+embedding硬底线+截断) -> rerank(reranked, DashScope/SiliconFlow Reranker+相对阈值+Top-30, RERANKER_ENABLED+RERANKER_QUERY_MODE 配置) -> judge(llm_judged -> selected, LLM invoke+JsonOutputParser 100并发单篇) -> snowball(expanded, LLM invoke+_parse_json_array query evolution + API re-search + 引文扩展) -> 评测 -> 四类产物
- 成功路径（mock）：query -> QueryPlan(规则) -> mock 检索 -> CandidatePool(seed) -> 跳过滚雪球 -> coarse_score(rough_scored) -> rerank(reranked) -> judge(llm_judged -> selected) -> 评测 -> 四类产物
- 失败路径：query 为空 -> CLI 参数错误或 API 返回错误；backend 不支持 -> ValueError 中断；单个外部 API 子查询失败 -> 记录 warning 后继续其他检索任务；预算耗尽 -> 跳过剩余 API 调用或迭代轮次

### 错误分支

- 查询为空
  - 触发条件：CLI 未提供 --query，或 Web/HTTP 请求未传 query
  - 处理方式：CLI 侧 parser.error；Web/API 返回 JSONResponse(status_code=400)
  - 影响范围：CLI 和 Web 入口层

- backend 不支持
  - 触发条件：指定非 mock/live 的 backend
  - 处理方式：抛出 ValueError，pipeline 中断
  - 影响范围：pipeline 层

- 外部 API 受限或失败
  - 触发条件：Semantic Scholar / OpenAlex 返回 429、HTTP 5xx 或请求超时
  - 处理方式：is_retryable 判断后按退避重试最多 3 次；不可重试或最终失败后记录日志并继续其他检索任务
  - 影响范围：live 初检索候选规模可能下降，但不必然阻断整条链路

- 预算耗尽
  - 触发条件：API 调用次数达到 max_api_calls 上限
  - 处理方式：BudgetController.can_call_api 返回 False，跳过剩余 S2/OA 检索任务
  - 影响范围：候选池规模减少

- golden set 未匹配
  - 触发条件：查询不在 golden_set.json 的 cases 中
  - 处理方式：返回空评测（precision/recall/f1 为 None）
  - 影响范围：评测指标缺失，不影响输出产物生成

- LangGraph 不可用
  - 触发条件：langgraph 库未安装或导入失败
  - 处理方式：`_build_snowball_graph` 返回 None，`run_snowball` 跳过并返回原始 pool 和空 edges
  - 影响范围：雪球扩展缺失，但不阻断后续筛选和输出

- 候选池状态非法转换
  - 触发条件：代码尝试执行 VALID_TRANSITIONS 中未定义的转换
  - 处理方式：CandidatePool.transition 抛出 InvalidTransition
  - 影响范围：pipeline 中断
